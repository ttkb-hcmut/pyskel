We thank the reviewers for their insightful comments.

# Review 1

The goal of skeletal semantics is to provide a simple way to describe semantics
that can be close to existing specifications and from which one may easily
derive other artefacts, such as interpreters or mechanized formalizations. This
is indeed a very crowded field, but we have not found other works that offer a
simple interface to build new backends. We will include short comparisons with
the suggested related work while revising the paper.

We have not yet considered free monads or interaction trees as interpretations
of skeletal semantics. This looks indeed like a promising approach to provide a
Coq semantics. The minimalism of Skel encourages such experiments.

One can indeed write types that are not strictly positive such as "type clos =
(ap : clos → clos)". This is for instance used in
https://gitlab.inria.fr/skeletons/necro-test/-/blob/master/lambda_ho.sk
However, type aliases must be strictly positive: the system rejects a
declaration like "type clos := clos → clos".

We do not give examples of static semantics in the paper, but we can capture
them as any inductive definition. See for instance
https://gitlab.inria.fr/skeletons/necro-test/-/blob/master/typed_cbn_lambda.sk#L49
for a simply-typed λ-calculus.

Monad inlining is useful when targeting descriptions that do not have monads or
first-class functions. For instance, the output of our Necro Debug tool is
difficult to read when using monads. Generating inductive definitions, e.g., to
typeset rules in LaTeX, also requires the elimination of monads.

# Review 2

The seminal paper on skeletal semantics did not include polymorphism nor first
class functions, and the language was more imperative than functional. In
addition, no tool to manipulate skeletal semantics existed, and the Coq proofs
accompanying the paper were all written by hand, including the embedding of the
languages considered. We rewrote most proofs as first-class functions are a
fundamental addition to the language.

We would agree to change the category of the paper as a system description.

# Review 3

An example of a meta-theory property we target is the proof of absence of
assertion failures in language specifications. In particular, we want to ensure
this property for an ongoing formalization of ECMAScript
(https://hal.inria.fr/hal-03509431v1).
